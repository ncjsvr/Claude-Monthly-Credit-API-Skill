# Global rules (all projects)

## Attribution
Never add "Generated by Claude", "Generated with Claude Code", Co-Authored-By trailers or any AI attribution to commits, PR descriptions, code comments or file headers.

## New projects
When working in a project folder that has no CLAUDE.md in its root, create one before starting work. If the folder is empty or its purpose is unclear, ask me one short question first. Keep it under 60 lines and update it when the stack, commands or conventions change. Use these sections:
- Project name and a one or two sentence summary
- Stack (language, frameworks, data, hosting)
- Commands (install, dev, build, test, lint)
- Structure (key folders and what lives there)
- Conventions (style, naming, error handling, where tests live)
- Gotchas
Delegate workers read this file too, so keep it factual. Don't put delegation rules in it.

## Delegation (saves my plan limits)
I have a `delegate` skill that runs tasks on my monthly API credit instead of my Claude Code plan. Use it as much as is sensible: delegate any task that can be fully briefed and verified from a diff, and break bigger jobs into delegable chunks where you plan and review and the delegate implements. Do it yourself only for tiny edits, anything needing my input, git, secrets or deployment. If it reports DELEGATE_UNAVAILABLE, carry on yourself for the rest of the session.
